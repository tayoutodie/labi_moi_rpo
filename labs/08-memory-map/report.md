# ЛР 8. Карта памяти

Система: **Windows 11 x64**, Python 3.12.10. Инструменты: `mem.py`, PowerShell `Get-Process`; полноценная карта VMMap не получена.

## Этапы mem.py
Старт: **`1. start`**, запуск подтверждён.
Получено 300 МиБ: **`2. got 300 MB`**, сообщение программы подтверждено; фактический прирост виртуальной памяти **не измерен**.
Запись в каждую страницу: **`3. wrote to every page`**, сообщение подтверждено; рабочий набор **не измерен**.
Освобождение: **`4. freed`**, сообщение подтверждено; память после освобождения **не измерена**.
Ожидаемый механизм: анонимное отображение памяти создаёт адресный диапазон, а обращение к страницам активирует их физическое обеспечение; конкретная динамика Working Set требует измерений.

## Карта памяти
Теоретически отображение включает исполняемый образ и DLL, стеки потоков, кучу, отображённые и свободные/зарезервированные диапазоны. **Реальная карта VMMap данного запуска не снималась.**

## Утечка
Пять измерений `leak.py`: **не проводились**.
Ожидаемый прирост по коду: 10 МиБ в секунду, то есть **около 20 МиБ за 2 секунды**, но **фактических значений нет**.

Не получилось: два запуска `mem.py` успешно дошли до `4. freed`; попытка внешнего мониторинга дала 16 одинаковых строк по PID 22664 (`VirtualMB=4248,22`, `WorkingSetMB=23,00`) без привязки к реально работающему PID, поэтому эти данные нельзя считать подтверждением изменения памяти на четырёх этапах. Лабораторная **частично выполнена**.

## Статус подтверждений

Данные разделов выше получены на Windows 11 студента, если прямо не обозначено CI. Результаты CI на Windows Server 2025 приведены отдельно и не заменяют локальные наблюдения. Некоторые кадры в `screenshots/` могут быть повторными или неполными; наличие файла не означает, что все требования экспериментально выполнены. Отсутствующие измерения обозначены явно.

## Объяснение этапов (Windows 11)

`mem.py` создаёт отображение анонимной памяти на 300 МБ, затем по очереди обращается к страницам и освобождает отображение.

- **Старт:** базовая виртуальная и физическая память процесса Python.
- **Резервирование 300 МБ:** виртуальное адресное пространство растёт, но физическое потребление может почти не измениться.
- **Запись в каждую страницу:** страницы становятся реально востребованными, рабочий набор обычно растёт.
- **Освобождение:** память может вернуться системе, но точный рабочий набор зависит от ОС, Python и учёта памяти.

Для наблюдения Windows удобно использовать VMMap или `Get-Process -Id <PID> | Select-Object VirtualMemorySize64,WorkingSet64`. `leak.py` добавляет примерно 10 МиБ данных в секунду, поэтому теоретический прирост за 2 секунды — около **20 МиБ**, но реальную память процесса нужно измерить.

**Не проведено в Windows 11:** четыре замера `mem.py`, пять точек `leak.py`, карта VMMap и 4 снимка. Данные раннего Linux-теста на 80 МиБ не являются выполнением опыта на 300 МБ.
